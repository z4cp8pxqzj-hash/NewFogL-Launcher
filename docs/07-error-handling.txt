================================================================================
NewFogL 补充文档 1 —— 错误处理规范
================================================================================

文档版本：1.1.0
适用范围：C++ 启动器 + Java 加载器
目的：统一错误分类、处理策略、退出码、日志格式、用户提示


================================================================================
第一部分  错误分类
================================================================================

--------------------------------------------------------------------------------
1.1  四级错误分类
--------------------------------------------------------------------------------

	级别		名称		处理方式				退出码
	------		--------	----------------------	--------
	L1			可忽略		记录 WARN，继续执行		—
	L2			可恢复		记录 ERROR，降级或跳过	—
	L3			致命		记录 FATAL，中止		1-4
	L4			内部错误	记录 FATAL + 堆栈		5


--------------------------------------------------------------------------------
1.2  L1：可忽略错误
--------------------------------------------------------------------------------

	定义：不影响流程正确性的异常情况。

	例子：
		· 模组的 recommends 依赖未安装
		· 元数据的某个可选字段缺失
		· 依赖版本范围描述过宽（如 ">=0.92.0" 没有上限）
		· 缓存文件过期

	处理：
		· 写入 WARN 日志
		· 继续执行
		· 不弹窗、不中止


--------------------------------------------------------------------------------
1.3  L2：可恢复错误
--------------------------------------------------------------------------------

	定义：当前步骤失败，但可以降级处理。

	例子：
		· 硬链接创建失败 → 降级为复制
		· 某个 jar 打不开 → 跳过该 mod，继续处理其他
		· 日志轮转失败 → 保留当前日志，不轮转

	处理：
		· 写入 ERROR 日志
		· 执行降级逻辑
		· 记录降级原因
		· 不中止


--------------------------------------------------------------------------------
1.4  L3：致命错误
--------------------------------------------------------------------------------

	定义：核心流程无法继续，必须中止。

	例子：
		· 五道红线任意一条触发
		· 依赖拓扑排序出现无法处理的环
		· 部署区文件被占用
		· 沙盒类加载器创建失败
		· Java 运行时不存在

	处理：
		· 写入 FATAL 日志
		· 写入 [STATE] ABORT <原因>
		· 设置对应退出码
		· 立即中止

		（当前实现情况：FatalArbitrationError 已携带该语义，但 Main 捕获后仅记录
		  FATAL 日志并 exit(1)，尚未真正打印 [STATE] ABORT 行。）


--------------------------------------------------------------------------------
1.5  L4：内部错误
--------------------------------------------------------------------------------

	定义：代码自身的 bug，未预料的异常。

	例子：
		· NullPointerException
		· ArrayIndexOutOfBoundsException
		· 未捕获的 RuntimeException
		· 断言失败

	处理：
		· 写入 FATAL 日志
		· 写入完整堆栈到 stderr
		· 设置退出码 5
		· 立即中止

第二部分  退出码对照表
================================================================================

--------------------------------------------------------------------------------
2.1  加载器退出码
--------------------------------------------------------------------------------

	退出码	含义					级别	弹窗标题
	------	----------------------	----	------------------------
	0		成功					—		—
	1		静态预检失败			L3		静态预检失败
	2		依赖解析失败			L3		依赖解析失败
	3		部署失败				L3		部署失败
	4		沙盒规划失败			L3		沙盒规划失败
	5		内部错误				L4		内部错误
	6		参数错误				L3		参数错误
	7		游戏进程拉起失败		L3		游戏进程拉起失败


	当前实现情况：加载器 Main 目前仅实际返回 1（预检失败）、5（内部错误）、
	6（参数错误）；2 / 3 / 4 / 7 虽在上表定义，尚未由加载器触发。


--------------------------------------------------------------------------------
2.2  启动器退出码
--------------------------------------------------------------------------------

	退出码	含义					触发场景
	------	----------------------	--------------------------
	0		成功					正常退出
	1		目录初始化失败			.minecraft 创建失败
	2		内嵌资源释放失败		解压失败或磁盘不足
	3		配置读取失败			NewFogL-config.json 损坏
	4		实例读取失败			instances\ 读取异常
	5		加载器拉起失败			CreateProcess 失败
	6		脚本执行失败			.bat 无法执行
	7		内部错误				未捕获异常


	当前实现情况：C++ 启动器尚未实现上表的退出码体系，实际仅：
	· 日志目录创建失败 → 返回 1；
	· 实例不存在 → 返回 1；
	· 其余情况透传加载器退出码或返回 0（自检成功）。


================================================================================
第三部分  日志格式规范
================================================================================

--------------------------------------------------------------------------------
3.1  格式
--------------------------------------------------------------------------------

	[时间戳] [级别] [模块] 原始消息

	字段			格式					必填
	------------	---------------------	--------
	时间戳			yyyy-MM-dd HH:mm:ss		是
	级别			DEBUG/INFO/WARN/ERROR/FATAL	是
	模块			固定枚举值				是
	原始消息		任意字符串				是


--------------------------------------------------------------------------------
3.2  各级别使用规则
--------------------------------------------------------------------------------

	DEBUG	调试细节			默认开启，不弹窗
	INFO	正常流程节点		记录关键步骤
	WARN	L1 可忽略错误		记录但不中止
	ERROR	L2 可恢复错误		记录降级原因
	FATAL	L3/L4 致命错误		记录后立即中止


--------------------------------------------------------------------------------
3.3  日志消息规范
--------------------------------------------------------------------------------

	要求：
		· 使用中文描述
		· 包含具体对象（哪个 mod、哪个文件、哪个路径）
		· 不包含换行符
		· 不包含制表符
		· 长度建议不超过 200 字符

	正例：
		[INFO] [Scanner] 发现 47 个 jar 文件
		[ERROR] [Deploy] 硬链接失败，降级复制: 跨盘符
		[FATAL] [PreFlight] MultiVersion: sodium 存在多个版本

	反例：
		[INFO] [Scanner] 扫描完成
		[ERROR] [Deploy] 出错了
		[FATAL] 失败


--------------------------------------------------------------------------------
3.4  多行消息处理
--------------------------------------------------------------------------------

	如果需要输出多行内容（如堆栈），使用多次日志调用：

		logger.error("Launcher", "捕获异常: " + e.getClass().getName());
		logger.error("Launcher", "异常消息: " + e.getMessage());
		for (StackTraceElement el : e.getStackTrace()) {
			logger.error("Launcher", "  at " + el.toString());
		}


--------------------------------------------------------------------------------
3.5  日志落盘策略
--------------------------------------------------------------------------------

	· 级别过滤：仅 DEBUG 可关闭（debugEnabled），INFO / WARN / ERROR / FATAL 始终输出。
	· 文件：所有模块、所有级别均先写入日志文件。
	· 控制台（Java NewFogLogger）：仅输出 ConsoleModules 白名单内的模块
	  （Scanner / PreFlight / Resolver / Arbiter / Deploy / Launcher / Game）。
	· 控制台（C++ Logger）：默认模块白名单同上，UI / Config / Instance 不输出。
	· 轮转：Java 侧 LogRotator 单文件超过 10 MB 切分、保留最近 5 个历史；
	  C++ 侧日志轮转尚未实现（当前版本未实现）。
	· UI 回调：C++ Logger 把所有日志转发给 UI 回调。


================================================================================
第四部分  用户提示规范
================================================================================

--------------------------------------------------------------------------------
4.1  弹窗消息结构
--------------------------------------------------------------------------------

	标题：错误类型（4-6 字）

	正文：
		【错误详情】
		{一句话描述}

		【涉及对象】
		· {对象1}
		· {对象2}

		【建议】
		{可操作的建议}

	按钮：
		[查看日志] [重新启动] [关闭]


--------------------------------------------------------------------------------
4.2  各类错误的标准提示
--------------------------------------------------------------------------------

	L3 静态预检失败（MultiVersion）：
		标题：检测到多版本模组
		详情：模组 sodium 存在多个版本
		涉及：sodium-0.5.8.jar、sodium-0.6.0.jar
		建议：请移除多余版本后重试

	L3 静态预检失败（CrossLoader）：
		标题：检测到违禁的跨加载器兼容层
		详情：模组 xxx 是 FORGE 模组，但依赖 fabric-api
		涉及：xxx-forge-1.0.jar
		建议：请移除该模组或更换其原生版本

	L3 依赖解析失败（DependencyMissing）：
		标题：依赖解析失败
		详情：模组 create 依赖 flywheel >= 0.6.0
		涉及：create-1.20.1-0.5.1.f.jar
		建议：请安装 flywheel 0.6.0 或更高版本

	L3 部署失败：
		标题：部署失败
		详情：硬链接创建失败，磁盘空间不足
		涉及：D:\MC\NewFogL\cache\工业时代\mods-deployed
		建议：请清理磁盘空间后重试

	L4 内部错误：
		标题：内部错误
		详情：NullPointerException at ModDeployer.deploy()
		涉及：NewFogL\logs\launcher.log
		建议：请将日志反馈给开发者


--------------------------------------------------------------------------------
4.3  禁止的提示风格
--------------------------------------------------------------------------------

	反例：
		"出错了"
		"操作失败，请重试"
		"Error: null"
		"Exception in thread main..."

	正确做法：
		· 说清楚是什么错误
		· 说清楚涉及哪个对象
		· 说清楚用户能做什么
		· 不做技术术语堆砌


================================================================================
第五部分  异常类设计规范
================================================================================

--------------------------------------------------------------------------------
5.1  Java 侧
--------------------------------------------------------------------------------

	自定义异常必须继承 RuntimeException。

	唯一自定义异常类：FatalArbitrationError

	字段：
		· redLine			红线名称
		· affectedMods		涉及模组列表
		· userMessage		用户可见提示
		· logMessage		日志记录消息

	构造方法：

		public FatalArbitrationError(
			String redLine,
			String userMessage,
			List<String> affectedMods
		);

	抛出规则：
		· 只在 L3 致命错误时抛出
		· 抛出后不再捕获，直接向上传递到 Main
		· Main 捕获后设置退出码 1


--------------------------------------------------------------------------------
5.2  C++ 侧
--------------------------------------------------------------------------------

	不使用异常。使用返回值 + 错误码。

	形式1：返回 bool

		bool createJunction(const std::string& target,
							const std::string& source);

	形式2：返回结构体

		struct Result {
			bool success;
			std::string errorMsg;
		};

		Result extractResources(const std::string& targetDir);

	形式3：出参

		bool loadConfig(const std::string& path, Config& out, std::string& err);


================================================================================
第六部分  错误日志与用户提示的分工
================================================================================

--------------------------------------------------------------------------------
6.1  分工原则
--------------------------------------------------------------------------------

	日志：面向开发者，包含技术细节
	弹窗：面向用户，包含操作建议

	两者不重叠：
		· 日志里有堆栈，弹窗里没有
		· 弹窗里有建议，日志里没有
		· 日志用中文，弹窗也用中文，但用词不同


--------------------------------------------------------------------------------
6.2  对应关系示例
--------------------------------------------------------------------------------

	触发：
		MultiVersionChecker 检测到 sodium 有两个版本

	日志（开发者看）：
		[2026-10-15 14:30:03] [ERROR] [PreFlight] MultiVersion: sodium 存在多个版本
		[2026-10-15 14:30:03] [ERROR] [PreFlight] 涉及模组: sodium-0.5.8.jar, sodium-0.6.0.jar

	弹窗（用户看）：
		标题：检测到多版本模组
		详情：模组 sodium 存在多个版本
		涉及：sodium-0.5.8.jar、sodium-0.6.0.jar
		建议：请移除多余版本后重试


================================================================================
第七部分  错误处理的代码检查清单
================================================================================

每个模块完成后，对照检查：

	□ 所有可能的错误都有对应的日志输出
	□ 错误级别选择正确（L1→WARN，L2→ERROR，L3/L4→FATAL）
	□ 日志消息包含具体对象，不是泛泛而谈
	□ 可恢复错误有降级逻辑
	□ 致命错误有对应的退出码
	□ 用户提示包含"详情 / 涉及 / 建议"三段
	□ 没有吞掉异常（catch 后不处理）
	□ 没有用 System.out.println 代替日志
	□ 没有在 L2 错误上中止流程
	□ 没有在 L3 错误上尝试继续
