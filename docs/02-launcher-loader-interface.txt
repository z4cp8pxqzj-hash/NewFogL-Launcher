================================================================================
New Fog 加载器 ↔ NewFogL 启动器 通讯接口文档
================================================================================

文档版本：1.1.0
通讯双方：
	加载器	New Fog Loader（newfog-loader.jar，Java）
	启动器	NewFogL（NewFogL.exe，C++）


================================================================================
一、通讯总览
================================================================================

启动器与加载器之间通过三种方式通讯：

	方式				方向			用途
	----------------	------------	--------------------------------
	命令行参数			启动器→加载器	传递实例信息、路径
	stdout 输出			加载器→启动器	日志 + 状态回传
	newfog-rules.json	加载器→启动器	启动计划（结构化数据）

	补充：
	- 启动器通过退出码判断加载器最终结果
	- 加载器不直接调用启动器，不建立 Socket
	- 双方不共享内存，不通过文件锁同步


================================================================================
二、调用协议
================================================================================

--------------------------------------------------------------------------------
2.1  调用命令
--------------------------------------------------------------------------------

启动器使用 ProcessBuilder 或 CreateProcess 执行：

	java -jar newfog-loader.jar ^
		--instance "<实例名>" ^
		--mods-dir "<mods 源目录>" ^
		--cache-dir "<cache 目录>" ^
		--versions-dir "<versions 目录>" ^
		--config "<实例配置文件路径>" ^
		--log-file "<日志文件路径>"


--------------------------------------------------------------------------------
2.2  参数定义
--------------------------------------------------------------------------------

参数			必填	类型	说明
------------	----	----	------------------------------------------
--instance		是		字符串	实例名，用于日志与标识
--mods-dir		是		路径	mod 源目录（用户放入 jar 的位置）
--cache-dir		是		路径	缓存与部署区根目录
--versions-dir	是		路径	实例目录根
--config		是		路径	instance.json 的完整路径
--log-file		是		路径	日志输出文件路径


		说明（当前版本实现情况）：
		- 上表为协议约定；当前加载器 Main 仅读取第 1 个位置参数作为 mods 目录，
		  尚未解析 --instance / --mods-dir / --cache-dir / --versions-dir /
		  --config / --log-file 这些具名参数（当前版本未实现）。
		- 启动器侧 ProcessLauncher 已按本表拼接并传入全部具名参数。


--------------------------------------------------------------------------------
2.3  参数示例
--------------------------------------------------------------------------------

	java -jar newfog-loader.jar ^
		--instance "工业时代" ^
		--mods-dir "D:\MC\NewFogL\mods\工业时代\mods" ^
		--cache-dir "D:\MC\NewFogL\cache\工业时代" ^
		--versions-dir "D:\MC\versions\工业时代" ^
		--config "D:\MC\versions\工业时代\instance.json" ^
		--log-file "D:\MC\NewFogL\logs\工业时代\runtime.log"


--------------------------------------------------------------------------------
2.4  参数校验规则
--------------------------------------------------------------------------------

	规则									失败退出码
	------------------------------------	------------
	必填参数缺失							6
	路径不存在或无法访问					6
	instance.json 解析失败					6
	路径包含非法字符						6


================================================================================
三、退出码
================================================================================

退出码	含义							启动器处理
------	----------------------------	--------------------------------
0		全部成功，启动计划已生成		继续执行启动脚本
1		静态预检失败（五道红线触发）	弹窗提示红线内容，中止
2		依赖解析失败（循环依赖无法处理）	弹窗提示，中止
3		部署失败（文件操作异常）		弹窗提示，中止
4		沙盒规划失败					弹窗提示，中止
5		内部错误（未捕获异常）			弹窗提示 + 日志路径
6		参数错误（缺少必填参数）		弹窗提示，中止
7		游戏进程拉起失败				弹窗提示，中止

	说明：
	- 退出码由加载器 main 方法通过 System.exit() 返回
	- 启动器必须等待加载器进程结束后读取退出码
	- 非 0 退出码时，启动器必须读取 stdout 最后几行日志以获取具体原因
	- 退出码 7 是加载器在"生成启动计划后、拉起游戏进程时"失败返回，
	  与退出码 3（部署失败）的区别：
		· 3 = 加载器自身文件操作失败（部署、硬链接、写清单）
		· 7 = 文件操作都成功，但 ProcessBuilder 拉起 jre-17 失败
		  （java.exe 路径无效、JVM 参数非法、游戏 jar 损坏等）
	- 加载器第 14.3 节、启动器第 8.1 节均使用 7 = GAME_LAUNCH_FAILED
	（当前实现情况：加载器 Main 目前仅实际返回 1 / 5 / 6；2 / 3 / 4 / 7 已在
	CrashDetector 中定义，但尚未由加载器触发。）


================================================================================
四、stdout 输出协议
================================================================================

加载器通过 stdout 输出两类信息：

	类型		前缀		用途
	--------	--------	------------------------------
	日志行		[时间戳]	流程日志，给人和启动器看
	状态行		[STATE]		关键节点通知，给启动器解析

	注意：
	- 所有输出必须走 stdout，不能走 stderr
	- stderr 只用于未捕获异常的堆栈（退出码 5 时）


--------------------------------------------------------------------------------
4.1  日志行格式
--------------------------------------------------------------------------------

	[时间戳] [级别] [模块] 原始消息

	字段说明：

	字段	格式					说明
	----	---------------------	--------------------------------
	时间戳	yyyy-MM-dd HH:mm:ss		精确到秒，不带毫秒
	级别	DEBUG/INFO/WARN/ERROR/FATAL	五个级别
	模块	见下表					固定枚举值
	消息	任意字符串				原始文本，不做翻译


--------------------------------------------------------------------------------
4.2  模块名清单
--------------------------------------------------------------------------------

模块名		用途
----------	----------------------------------------
Scanner		扫描 mod 目录
PreFlight	静态预检
Resolver	依赖解析
Arbiter		仲裁决策
Deploy		部署与重命名
Launcher	启动脚本生成与计划输出
Game		游戏进程输出（由启动器转发，加载器不输出）


--------------------------------------------------------------------------------
4.3  日志示例
--------------------------------------------------------------------------------

	[2026-10-15 14:30:01] [INFO] [Scanner] 开始扫描: D:\MC\NewFogL\mods\工业时代\mods
	[2026-10-15 14:30:01] [INFO] [Scanner] 发现 47 个 jar 文件
	[2026-10-15 14:30:02] [INFO] [Scanner] 解析完成，47 个 ModDescriptor
	[2026-10-15 14:30:02] [INFO] [PreFlight] 开始静态预检
	[2026-10-15 14:30:02] [INFO] [PreFlight] 多版本拦截: 通过
	[2026-10-15 14:30:02] [WARN] [PreFlight] 模组 jei 的依赖版本范围过宽: [15.0,)
	[2026-10-15 14:30:03] [ERROR] [PreFlight] 依赖缺失: create 需要 flywheel >= 0.6.0
	[2026-10-15 14:30:03] [FATAL] [Launcher] 预检失败，中止启动


--------------------------------------------------------------------------------
4.4  状态行格式
--------------------------------------------------------------------------------

	[STATE] <阶段> <结果>

	字段说明：

	字段	说明
	----	------------------------------------
	阶段	固定枚举值（见下表）
	结果	随阶段不同，见下表


--------------------------------------------------------------------------------
4.5  状态行清单
--------------------------------------------------------------------------------

阶段				结果			说明
----------------	------------	--------------------------------
SCAN_START			—				开始扫描
SCAN_DONE			<数量>			扫描完成，输出模组数量
PREFLIGHT_START		—				开始静态预检
PREFLIGHT_DONE		PASS / FAIL		预检结果
RESOLVE_START		—				开始依赖解析
RESOLVE_DONE		PASS / FAIL		解析结果
DEPLOY_START		—				开始部署
DEPLOY_DONE			<数量>			部署完成，输出文件数
SANDBOX_START		—				开始沙盒规划
SANDBOX_DONE		PASS / FAIL		沙盒结果
PLAN_READY			<脚本路径>		启动计划已生成
ABORT				<原因>			中止


--------------------------------------------------------------------------------
4.6  状态行示例
--------------------------------------------------------------------------------

	[STATE] SCAN_START
	[STATE] SCAN_DONE 47
	[STATE] PREFLIGHT_START
	[STATE] PREFLIGHT_DONE PASS
	[STATE] RESOLVE_START
	[STATE] RESOLVE_DONE PASS
	[STATE] DEPLOY_START
	[STATE] DEPLOY_DONE 47
	[STATE] SANDBOX_START
	[STATE] SANDBOX_DONE PASS
	[STATE] PLAN_READY D:\MC\NewFogL\scripts\工业时代.bat


	说明（当前实现情况）：加载器 Java 侧 Main 目前尚未输出任何 [STATE] 行
	（仅有普通日志行），StateParser 已具备完整解析能力，该状态行输出待补充。


--------------------------------------------------------------------------------
4.7  启动器解析规则
--------------------------------------------------------------------------------

	1. 逐行读取 stdout
	2. 以 [STATE] 开头的行 → 解析状态并更新 UI
	3. 以 [时间戳] 开头的行 → 解析日志并显示到日志面板
	4. 其他行 → 原样显示
	5. 进程退出后，读取退出码判断结果

	当前实现情况：LogForwarder 不区分第 3 / 4 类行，凡非 [STATE] 行一律原样
	转发给 UI（“解析日志”与“原样显示”合并为一次转发，该细分未实现）。


================================================================================
五、启动计划文件
================================================================================

加载器完成全部阶段后，生成 newfog-rules.json，供启动器读取。

--------------------------------------------------------------------------------
5.1  文件路径
--------------------------------------------------------------------------------

	NewFogL\cache\{实例名}\newfog-rules.json


--------------------------------------------------------------------------------
5.2  文件结构
--------------------------------------------------------------------------------

	{
		"instanceName": "工业时代",
		"gameVersion": "1.20.1",
		"loader": "mixed",
		"loaderVersion": "mixed",
		"javaVersion": 17,
		"javaPath": "runtime\\jre-17\\bin\\java.exe",
		"scriptPath": "NewFogL\\scripts\\工业时代.bat",
		
		"sandboxes": [
			{
				"loader": "FORGE",
				"classLoaderName": "NewFogSandboxClassLoader-Forge-1",
				"sharedLibs": ["architectury", "mixin"],
				"privateLibs": ["forge-47.4.26"],
				"mods": ["F-001", "F-002", "F-003"]
			}
		],
		
		"loadOrder": ["B-001", "F-001", "F-002", "N-001"],
		"cycleGroups": [],
		
		"shortIdMap": {
			"forge:jei": "F-001",
			"fabric:sodium": "B-015"
		}
	}


--------------------------------------------------------------------------------
5.3  字段说明
--------------------------------------------------------------------------------

字段				类型		说明
----------------	--------	----------------------------------
instanceName		字符串		实例名
gameVersion			字符串		固定 "1.20.1"
loader				字符串		mixed（当前由加载器固定写 "mixed"，各加载器归属见 sandboxes[].loader）
loaderVersion		字符串		加载器版本
javaVersion			整数		17 或 21
javaPath			字符串		Java 可执行文件路径
scriptPath			字符串		生成的 .bat 路径
sandboxes			数组		沙盒规划结果
loadOrder			数组		模组加载顺序（短编号）
cycleGroups			数组		环组列表（如有循环依赖）
shortIdMap			对象		全局长 ID → 短编号映射


--------------------------------------------------------------------------------
5.4  解析归属与时机
--------------------------------------------------------------------------------

	加载器写完 newfog-rules.json 后，由启动器的【ipc 层】负责读取和解析。
	具体分工：

		角色          	文件                	职责
		--------------	--------------------	--------------------------------
		ipc/RulesParser	newfog-rules.json   	读取 + 解析为结构体
		ipc/StateParser	stdout 的 [STATE] 行	逐行解析 + 更新 UI 状态
		main 流程     	—                  	在 [STATE] PLAN_READY 后
		              	                    	调用 RulesParser，拿 scriptPath

	读取时机（严格顺序）：

		1. ProcessLauncher 拉起加载器，回调 onOutput 逐行转发
		2. StateParser 解析 [STATE] 行
		3. 遇到 [STATE] PLAN_READY <脚本路径> →
		   触发 RulesParser::load(cacheDir/newfog-rules.json)
		4. 校验 rules.scriptPath 与 [STATE] 行给的路径一致
		   不一致 → 记 WARN，以 [STATE] 行为准（更实时）
		5. 加载器进程退出码非 0 → 不调用 RulesParser
		6. 退出码为 0 → 从 rules 取 scriptPath，执行 .bat

		当前实现情况：RulesParser::load 在回调收到 PLAN_READY 时立即调用（不等进程退出），
		上述第 4 步的路径一致性校验与第 6 步的 .bat 执行尚未实现。
		（LaunchFlow::run 读到 PLAN_READY 后仅解析 newfog-rules.json 并记录 scriptPath。）

	读取后使用范围：

		字段          	是否使用	用途
		--------------	--------	--------------------------------
		scriptPath    	是      	执行启动脚本
		javaPath      	是      	二次校验 java.exe 存在
		instanceName  	是      	日志展示
		loaderVersion 	是      	日志展示
		gameVersion   	是      	校验等于 "1.20.1"
		sandboxes     	仅日志  	UI 展示"沙盒 X 个"
		loadOrder     	仅日志  	UI 展示"加载顺序 Y 个"
		cycleGroups   	仅日志  	有环组时 UI 警示
		shortIdMap    	否      	仅加载器内部使用

	不负责（明确划出边界）：

		· 启动器不解析 sandboxes 里的 classLoaderName / sharedLibs / privateLibs
		· 启动器不根据 loadOrder 重排加载顺序（加载顺序由加载器决定）
		· 启动器不校验 shortIdMap 与 loadOrder 的一致性
		  （两个都是加载器生成，启动器只读展示）

	对齐要求：
		· 两个表格的表头 / 分隔行 / 数据行，列分隔用相同 Tab 数
		· "main 流程" 的续行 "调用 RulesParser，拿 scriptPath" 的
		  起始列要与同表其他行的"职责"列起始列一致


--------------------------------------------------------------------------------
5.5  启动器使用方式
--------------------------------------------------------------------------------

	1. 读取 scriptPath，得到 .bat 路径
	2. 读取 javaPath，确认 Java 可执行文件
	3. 读取 sandboxes，仅用于日志展示
	4. 读取 loadOrder，仅用于日志展示
	5. 执行 .bat 脚本，拉起游戏


================================================================================
六、启动脚本约定
================================================================================

--------------------------------------------------------------------------------
6.1  脚本路径
--------------------------------------------------------------------------------

	NewFogL\scripts\{实例名}.bat


--------------------------------------------------------------------------------
6.2  脚本内容约定
--------------------------------------------------------------------------------

	· 使用相对路径（以 %~dp0.. 为基准）
	  （当前实现改为“相对脚本自身所在目录”，基于 Path.relativize；%~dp0.. 基准未采用）
	· UTF-8 无 BOM 编码
	· 第一行 chcp 65001 >nul
	· 包含 --gameDir、--assetsDir、-cp 等完整启动参数
	· 游戏异常退出时 pause 等待用户查看


--------------------------------------------------------------------------------
6.3  脚本示例
--------------------------------------------------------------------------------

	@echo off
	chcp 65001 >nul
	title New FogL - 工业时代

	set "NF_ROOT=%~dp0.."
	set "INSTANCE=工业时代"
	set "GAME_DIR=%NF_ROOT%\versions\%INSTANCE%"
	set "MODS_DIR=%NF_ROOT%\NewFogL\cache\%INSTANCE%\mods-deployed"
	set "CONFIG_DIR=%NF_ROOT%\NewFogL\cache\%INSTANCE%\configs"
	set "JAVA=%NF_ROOT%\runtime\jre-17\bin\java.exe"

	cd /d "%GAME_DIR%"

	"%JAVA%" ^
		-Xmx8G -Xms4G ^
		-Dfabric.config.dir="%CONFIG_DIR%" ^
		-cp "%MODS_DIR%\*;..." ^
		net.minecraft.client.main.Main ^
		--gameDir "%GAME_DIR%" ^
		--version 1.20.1

	if errorlevel 1 (
		echo.
		echo [NewFogL] 游戏异常退出，错误码: %errorlevel%
		pause
	)


--------------------------------------------------------------------------------
6.4  启动器执行方式
--------------------------------------------------------------------------------

	C++ 侧使用 CreateProcess 执行：

		CreateProcess(
			NULL,
			"cmd.exe /c \"" + scriptPath + "\"",
			...
		);

	要求：
	- 重定向 stdout/stderr 到管道
	- 记录进程句柄 PID
	- 后台线程等待进程退出
	- 退出后读取退出码，触发守护逻辑

七、错误信息协议

--------------------------------------------------------------------------------
7.1  红线触发时的 stdout 输出
--------------------------------------------------------------------------------

	[ERROR] [PreFlight] <红线名称>: <详细信息>

	DependencyMissing	依赖解析失败
	FakeMod				检测到套壳模组
	CrossDuplicate		同一模组存在于多个加载器


--------------------------------------------------------------------------------
7.3  错误输出示例
--------------------------------------------------------------------------------

	[2026-10-15 14:30:03] [ERROR] [PreFlight] MultiVersion: sodium 存在多个版本

八、职责边界
================================================================================

--------------------------------------------------------------------------------
8.1  加载器负责
--------------------------------------------------------------------------------

	· 扫描 mod 目录
	· 解析元数据
	· 五道红线静态预检
	· 依赖解析与拓扑排序
	· 部署与重命名
	· 沙盒规划
	· 生成启动脚本
	· 输出日志与状态


--------------------------------------------------------------------------------
8.2  启动器负责
--------------------------------------------------------------------------------

	· UI 界面
	· 进程管理（拉起加载器、拉起游戏）
	· 守护（崩溃检测）
	· 文件操作（Junction、导出/导入）
	· IPC 通信
	· 日志显示（转发加载器和游戏的日志）
	· 内嵌资源释放


--------------------------------------------------------------------------------
8.3  互不干涉项
--------------------------------------------------------------------------------

	事项					谁负责
	--------------------	----------------
	扫描 mod				加载器
	创建实例目录			启动器
	部署重命名				加载器
	建立 Junction			启动器
	脚本执行				启动器
	崩溃检测				启动器
	导出整合包				启动器
	导入整合包				启动器
	预检（导入后）			加载器（用户启动时）
