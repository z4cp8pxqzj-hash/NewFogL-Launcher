================================================================================
第一部分  模块概述
================================================================================

NewFogL 启动器是整个项目的"外壳"，负责 UI、进程管理、守护、文件操作、
内嵌资源释放、导出/导入整合包。

职责范围：

	· UI 界面
	· 进程管理（拉起 Java 21 加载器、监控退出）
	· 守护（崩溃检测、崩溃提示）
	· 文件操作（复制、删除、硬链接、Junction）
	· 内嵌资源释放（首次启动时解压到 %TEMP% 和 .minecraft）
	· 导出/导入整合包（纯文件操作）
	· 建立 Junction 重定向
	· IPC 通信（接收加载器状态回传）
	· 日志显示（转发加载器和游戏的日志）

不负责：

	· 扫描 mod 目录（加载器负责）
	· 解析 mod 元数据（加载器负责）
	· 五道红线预检（加载器负责）
	· 依赖解析与拓扑排序（加载器负责）
	· 部署与重命名（加载器负责）
	· 沙盒规划（加载器负责）


================================================================================
第二部分  进程树
================================================================================

	NewFogL.exe (C++)
		│
		├── java.exe (jre-21)   ← New Fog 加载器
		│       │
		│       └── java.exe (jre-17)   ← 游戏进程
		│
		└── （启动器自身 UI 线程，不阻塞）


说明：

	· 启动器使用 jre-21 拉起加载器
	· 加载器使用 jre-17 拉起游戏
	· 启动器通过读取加载器进程的退出码判断最终结果
	· 启动器不直接拉起游戏进程

6.4  FileLock.h / FileLock.cpp

	方法：

	bool isFileLocked(const std::string& path) {
		HANDLE h = CreateFileA(path.c_str(),
							   GENERIC_READ | GENERIC_WRITE,
							   0,                     // dwShareMode = 0：独占
							   nullptr,
							   OPEN_EXISTING,
							   FILE_ATTRIBUTE_NORMAL,
							   nullptr);

		if (h == INVALID_HANDLE_VALUE) {
			DWORD err = GetLastError();
			// 文件不存在不算"被占用"
			if (err == ERROR_FILE_NOT_FOUND || err == ERROR_PATH_NOT_FOUND) {
				return false;
			}
			// 其他原因（共享冲突 / 权限不足等）视为不可用
			return true;
		}

		// 打开成功 → 没有其他进程占用 → 关闭句柄
		CloseHandle(h);
		return false;
	}

	bool isDirectoryLocked(const std::string& dir) {
		for (const auto& file : FileUtil::listFiles(dir)) {
			if (isFileLocked(file)) {
				return true;
			}
		}
		return false;
	}

	ProcessResult ProcessLauncher::executeAndWait(
		const std::string& cmdLine,
		const std::string& workingDir,
		std::function<void(const std::string&)> onOutput) {

		SECURITY_ATTRIBUTES sa = { sizeof(sa), NULL, TRUE };
		HANDLE hReadPipe, hWritePipe;
		CreatePipe(&hReadPipe, &hWritePipe, &sa, 0);

		STARTUPINFOA si = { sizeof(si) };
		si.dwFlags = STARTF_USESTDHANDLES;
		si.hStdOutput = hWritePipe;
		si.hStdError = hWritePipe;

		PROCESS_INFORMATION pi = { 0 };

		CreateProcessA(
			NULL,
			const_cast<char*>(cmdLine.c_str()),
			NULL, NULL, TRUE,
			CREATE_NO_WINDOW,
			NULL,
			workingDir.c_str(),
			&si, &pi
		);

		CloseHandle(hWritePipe);

		std::string output;
		std::thread reader([&]() {
			char buffer[4096];
			DWORD bytesRead;
			while (ReadFile(hReadPipe, buffer, sizeof(buffer) - 1,
							&bytesRead, NULL) && bytesRead > 0) {
				buffer[bytesRead] = '\0';
				std::string line(buffer);
				output += line;
				if (onOutput) onOutput(line);
			}
		});

		WaitForSingleObject(pi.hProcess, INFINITE);

		DWORD exitCode;
		GetExitCodeProcess(pi.hProcess, &exitCode);

		reader.join();
		CloseHandle(pi.hProcess);
		CloseHandle(pi.hThread);
		CloseHandle(hReadPipe);

		return { exitCode, output, "" };
	}

	· 源（真实存放地）= NewFogL\cache\{实例名}\{dir}
	· 目标（游戏读取地）= versions\{实例名}\{dir}
	· 只管标准目录，不管单文件（如 options.txt）

13.3  阶段2：游戏核心校验
--------------------------------------------------------------------------------

	1. LaunchFlow 检查实例是否存在（InstanceManager::exists）
		· 不存在 → 上报错误并返回退出码 1
	2. 检查 versions\{实例名}\1.20.1.jar 与 1.20.1.json
		· 缺失 → 从官方源下载后继续
		· 存在但校验失败（jar 内 version.json 的 id != "1.20.1"）→ 重新下载覆盖

	官方源下载步骤（设计）：

		· 拉取 version_manifest_v2.json，取 1.20.1 的版本 json 地址
		· 下载 1.20.1.json 到 versions\{实例名}\
		· 解析 json 内 downloads.client.url 与 sha1，下载 client jar 存为 1.20.1.jar
		· 按 sha1 校验；失败则重试（次数遵循 download.maxThreads/重试配置）

	说明：

		· 上述下载与校验当前版本未实现，现仅检查实例目录是否存在

13.4  阶段3：Java 运行时校验
--------------------------------------------------------------------------------

	1.（当前版本未实现）检测实例配置的 javaPath 是否存在
	2.（当前版本未实现）不存在 → 检查 javaErrorPrompt.showMissingJava
	3.（当前版本未实现）检测 Java 版本是否匹配
	4.（当前版本未实现）检测加载器与 Java 兼容性

		  上述校验尚未接入


--------------------------------------------------------------------------------
13.5  阶段4~10：调用加载器
--------------------------------------------------------------------------------

	由 app/LaunchFlow::run 编排，按顺序：

	1. 校验实例（InstanceManager::exists / load）
	2. 同步目录（JunctionSync::syncAll）
	3. 解析路径（PathResolver）：
		· jre21Path   = runtime\jre-21\bin\java.exe
		· loaderJar   = NewFogL\core\newfog-loader.jar
		· modsDir     = NewFogL\mods\{实例名}\mods
		· cacheDir    = NewFogL\cache\{实例名}
		· versionsDir = versions\{实例名}
		· configPath  = versions\{实例名}\instance.json
		· logFilePath = NewFogL\logs\{实例名}\runtime.log
	4. 拉起加载器（ProcessLauncher::launchLoader）：

		ProcessResult result = ProcessLauncher::launchLoader(
			jre21Path, loaderJar, instanceName,
			modsDir, cacheDir, versionsDir, configPath, logFilePath,
			[&](const std::string& line) { /* 逐行回调 */ }
		);

		· 命令行按 02 号接口文档 2.1 节拼接（--instance / --mods-dir
		  / --cache-dir / --versions-dir / --config / --log-file）
		· 工作目录 = versionsDir；stdout 与 stderr 合并到同一条管道
	5. 逐行处理回调输出：
		· 以 [STATE] 开头 → StateParser::parseState 解析
			- 命中 PLAN_READY → RulesParser::load(cacheDir\newfog-rules.json)
		· 其他行 → LogForwarder::forward 转发到 UI 回调


--------------------------------------------------------------------------------
13.6  阶段11：处理加载器结果
--------------------------------------------------------------------------------

	加载器退出后由 LaunchFlow 处理：

	CrashType crash = CrashDetector::detect(result.exitCode);
	if (crash != CrashType::NONE) {
		std::string reason = CrashAnalyzer::analyze(logFilePath);
		// 以日志形式上报：崩溃类型 + 分析结论
		return static_cast<int>(result.exitCode);
	}
	// 退出码 0：正常退出

	说明：

		· 当前版本以日志回调输出崩溃信息，不弹 CrashDialog（未实现）
		· 退出码 → 崩溃类型映射见 8.1 节


--------------------------------------------------------------------------------
13.7  阶段12~13：运行时监控与退出清理
--------------------------------------------------------------------------------

	1. LaunchFlow 返回退出码给启动线程
	2. MainWindow 的启动线程在日志面板追加"流程结束"
	3. UI 恢复"启动游戏"按钮

	说明：

		· 更新实例 lastLaunched / lastResult，以及把 options.txt 等单文件
		  同步回缓存区，当前版本未实现
		· 启动线程模型见 13.8 节


--------------------------------------------------------------------------------
13.8  app/LaunchFlow（启动流程编排）
--------------------------------------------------------------------------------

	职责：

	· 串联 config / instance / process / ipc / guardian 各层，完成一次启动
	· 把加载器 stdout 与内部状态实时回调给调用方（UI）

	方法：

	static int run(const std::string& instanceName,
				   std::function<void(const std::string&)> onOutput = nullptr);

	· 阻塞执行，返回进程退出码（0 表示成功）
	· onOutput 为空时内部直接丢弃状态信息

	UI 线程模型（ui/MainWindow::handleLaunch）：

	1. 切换到日志页并追加"准备启动实例"
	2. QThread::create 开子线程，在子线程内调用 LaunchFlow::run
	3. 回调经 QMetaObject::invokeMethod（Qt::QueuedConnection）
	   回到主线程，写入 LogPanel
	4. 线程结束 connect finished → deleteLater
	5. 子线程内 try/catch 兜底，避免异常导致崩溃
